# US-002: OCR Microservice API

**As a:** Developer / System Integrator  
**I want:** A microservice that requires a valid API Key to process images (POST) and lets me check its status (GET)  
**So that:** I can control access to the OCR service and monitor its availability  

## Acceptance Criteria

| Scenario | Given | When | Then |
|----------|-------|------|------|
| **Authorized Access (API Key)** | The service receives a POST request with an API Key in the header | The middleware queries the database and confirms the key exists and is valid | The service allows the image to be processed and returns success `200` |
| **Access Denied (Invalid API Key)** | The service receives a POST request with an incorrect or expired API Key | The middleware queries the database and the key is not valid | The service rejects the request with an HTTP `401` Unauthorized or `403` Forbidden code |
| **No API Key** | The service receives a POST request without the authentication header | The middleware intercepts the request before processing | The service returns an HTTP `401` error indicating that `the API Key is required` |
| **Image Validation** | The request has a valid API Key | The request body does not contain a valid image | The service returns an HTTP 400 Bad Request code |
| **Status Check (Health Check)** | The microservice is running | A GET request is made to the `/health` endpoint | The service responds with HTTP `200` and status "OK" (usually public for monitoring) |
| **Database Error** | The service tries to validate the API Key | The keys database is not available | The service returns an HTTP `500` error indicating an internal validation failure |
